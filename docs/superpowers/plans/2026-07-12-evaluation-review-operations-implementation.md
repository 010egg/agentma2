# AgentMa 评估系统审核与运维整改实施计划

日期：2026-07-12

## 目标

在现有评测模块中完成并行调度、候选用例级审核、项目级统计、项目归档/删除和可识别候选名称，并保持旧运行兼容。

## 实施步骤

1. 扩展 SQLite 模型：运行并发、候选别名、用例审核事件和尝试审核事件。
2. 增加审核聚合函数和项目指标查询，候选通过率按“候选 × 用例”计算。
3. 增加项目归档、恢复和事务删除；活动运行阻止永久删除。
4. 调整候选快照命名，在线候选固定为“模板名 · 模型名”，别名单独保存。
5. 调整队列领取顺序和每运行并发限制，优先并行同一用例的不同候选并兼顾多运行公平性。
6. 扩展评测 API：项目筛选、项目生命周期、审核矩阵、用例审核和尝试审核。
7. 更新评测页面：项目筛选、项目操作、候选别名、并发设置、分组证据与逐项审核。
8. 扩展存储/API smoke，验证审核聚合、项目隔离、删除保护、命名和并发限制。
9. 运行 ESLint、生产构建和回归 smoke；重启生产服务并验证线上接口。

## 兼容策略

- 新列使用幂等迁移和默认值。
- 旧候选继续读取 `name`；新候选额外保存 `alias`。
- 旧运行没有细粒度审核时，从尝试的 `passed` 派生候选用例结论。
- 运行级审核表继续作为报告发布签署，不参与样本通过率。
- 数据集和评分模板为租户共享资源，删除项目时保留。
