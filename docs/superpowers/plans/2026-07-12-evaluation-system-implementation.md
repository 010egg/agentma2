# AgentMa 评估系统实施计划

日期：2026-07-12

## 目标

按已批准的统一评测核心设计交付首个可运行版本：管理员可以维护评测项目、QA 测试集和评分模板，配置在线或离线候选，启动评测，查看自动评分和候选排行，并由指定审核人完成终审。代码修复流程同时落地安全执行器边界、命令建议和预检；未获得安全执行器时拒绝执行。

## 安全决策

采用独立 OS 沙箱执行器，不把验证命令包装成 Agent 会话：

- macOS Provider 使用 `/usr/bin/sandbox-exec`，默认禁止网络，只允许评测工作区和系统临时目录写入。
- 执行器通过统一接口暴露能力检测、预检和命令执行。
- 非 macOS 平台未配置安全 Provider 时，代码修复运行返回 `sandbox_unavailable`，不允许宿主机裸执行。
- 首个版本只实现命令建议、安全预检和执行器验证；完整仓库克隆、Agent 修复及补丁评测在核心 QA 纵向切片稳定后继续扩展。

## 实施步骤

### 1. 持久化与领域类型

- 新增独立 `server-evaluation-store.ts`，由 `server-store.ts` 注入现有 SQLite 连接。
- 创建项目、数据集、数据集版本、用例、评分模板、运行、候选、尝试和审核表。
- 所有查询带 `tenant_id`，审核人只读取被分配运行。
- 提供稳定的映射、JSON 校验和状态转换函数。

### 2. QA 评分引擎

- 支持精确答案、必含关键词、禁用关键词、正则和 JSON 结构断言。
- 指标统一为 0–100，保存分项证据、总分和通过阈值。
- 离线候选直接读取按 `caseId` 映射的回答。
- 在线候选调用现有 `runAgent()`，显式执行配额检查并记录 Token 账本。
- 裁判阶段首版使用结构化 Judge Agent；未配置裁判模型时进入人工审核并标记 `judge_unavailable`，不伪造分数。

### 3. 队列与运行生命周期

- 数据库作业按“候选 × 用例 × 重复序号”生成。
- 进程内 Worker 使用数据库租约领取任务，支持服务重启恢复过期任务。
- 状态按 `draft → queued → running → judging → awaiting_review → completed` 推进。
- 支持取消、失败任务重试和聚合报告。

### 4. 代码修复安全边界

- 新增 `server-evaluation-sandbox.ts`。
- 识别 Node、Python、Go、Rust 项目并给出命令建议。
- 预检操作系统、沙箱工具、工作区路径和命令格式。
- 添加 smoke 测试，证明沙箱内可写工作区、不可写工作区外文件、默认不可联网。

### 5. HTTP API

- 新增 `server-evaluations.ts` 并挂载 `/api/evaluations/*`。
- 管理写操作要求 `tenant_admin`。
- 被分配审核的成员可读取对应运行并提交审核，不能改配置。
- 创建、启动、取消和审核写入现有审计日志。

### 6. 运维控制台

- 新增 `/evaluations` 页面和侧边栏入口。
- 页面采用紧凑的运维工作台：总览指标、运行表、项目/数据集/模板标签页、新建运行抽屉、排行与审核详情。
- 状态变化通过轮询刷新；大列表分页或按需加载。
- 在窄屏下保持表单、工具栏和表格可用，无文字重叠。

### 7. 验证

- 添加存储、评分、权限、运行状态和沙箱 smoke 测试。
- 运行 `npm run build`、相关 smoke 脚本和现有关键回归测试。
- 启动本地服务，用浏览器检查管理员评测流程的桌面与移动布局。

## 首次交付边界

本次实现以 QA 在线/离线评测的完整闭环为主，并提供代码修复安全基础设施。代码修复不会在没有可靠沙箱、仓库准备和补丁采集验证的情况下显示为“可运行”。界面会明确展示 Provider 状态和不可用原因。
